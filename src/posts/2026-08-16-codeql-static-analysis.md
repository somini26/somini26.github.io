코드를 읽으면서 위험한 부분을 찾는 것도 중요하지만, 입력이 여러 함수를 거쳐 흘러갈 때는 놓치기 쉬운 부분이 있다. 그래서 이번에는 **CodeQL**을 이용해 데이터가 어디에서 들어오고 어디까지 전달되는지 찾아보았다.

## 이번 실습의 목표

사용자 입력 `input()`을 **Source**, 명령 실행 함수 `os.system()`을 **Sink**로 지정하여, 입력값이 별도 검증 없이 위험한 함수로 전달되는 흐름을 찾아보는 실습이었다.

```python
import os

command = input("Command: ")
os.system(command)
```

위 예시는 사용자가 입력한 문장을 운영체제 명령으로 전달한다. 문제는 단순히 `os.system()`이 코드에 있다는 사실이 아니라 **외부 입력이 제어 없이 명령 실행으로 이어진다**는 점이다.

## CodeQL에서 살펴본 내용

CodeQL은 코드를 분석 가능한 데이터베이스로 구성하고, QL 쿼리로 관심 있는 요소와 관계를 조회하는 방식이다. 이번에는 입력점과 위험 함수 호출의 관계를 정의하고, 데이터 흐름이 실제로 이어지는지 탐색했다.

쿼리를 작성하면서는 Python의 함수 호출 구조를 정확히 지정하고, Source와 Sink를 너무 광범위하게 잡지 않는 것이 중요했다. 잘못 정의하면 예상하지 않은 결과가 나오거나 탐지 자체가 되지 않을 수 있었다.

## 분석 결과에서 중요한 점

이 실습은 공개된 서비스에서 실제 버그바운티 취약점을 제보한 경험이 아니라 **정적 분석 도구의 탐지 원리를 익힌 실습**이다. 결과를 해석할 때는 경고 위치만 보는 게 아니라 데이터가 어디에서 시작해 어떤 경로로 전달되는지 확인해야 한다.

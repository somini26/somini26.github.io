`지그재그`는 RSA에서 사용하는 두 소수 `p`, `q`의 일부 비트가 엇갈려 공개된 문제였다. 각각의 절반만 보이니 정보가 모자라 보였지만, 곱한 결과인 `n`도 함께 주어졌다.

이 조건을 이용해 **자리올림을 계산하며 비트를 한 자리씩 복원**했다. 어떤 비트가 알려져 있을 때 나머지 비트를 결정할 수 있는지 정리해 본다.

---

## 1. 문제 분석

문제는 일반적인 RSA 암호문과 함께 두 소수 `p`, `q`의 일부 비트를 공개한다.

```python
mask_p = 0
mask_q = 0

for i in range(512):
    if i & 1:
        mask_p |= 1 << i
    else:
        mask_q |= 1 << i

mask_p = p & mask_p  # p의 홀수 번째 비트
mask_q = q & mask_q  # q의 짝수 번째 비트
```

즉 `p`의 1, 3, 5, ... 번째 비트와 `q`의 0, 2, 4, ... 번째 비트가 노출된다. 각 소수의 절반만 공개된 것처럼 보이지만, `n = p × q`를 이용하면 나머지 비트도 복구할 수 있다.

## 2. 취약점

`p`와 `q`를 이진수로 표현하면 다음과 같다.

```text
p = Σ p_i × 2^i
q = Σ q_i × 2^i
```

곱셈 결과 `n = pq`의 `k`번째 비트를 계산할 때 사용되는 값은 다음과 같다.

```text
S_k = carry_k + Σ(i=0..k) p_i × q_(k-i)
n_k = S_k mod 2
carry_(k+1) = floor(S_k / 2)
```

`p`, `q`는 모두 홀수인 소수이므로 `p_0 = q_0 = 1`이다. `k`번째 단계에서 새로 등장하는 항은 `p_kq_0 + p_0q_k = p_k + q_k`이다.

문제에서 `k`가 홀수면 `p_k`가 공개되고, `k`가 짝수면 `q_k`가 공개된다. 따라서 항상 둘 중 하나를 알고 있으며, `n`의 해당 비트와 이전 단계의 올림값을 이용해 나머지 하나를 결정할 수 있다. 예를 들어 `k`가 홀수라면 다음 관계를 사용한다.

```text
q_k = (n_k - carry_k - Σ(i=1..k-1) p_i × q_(k-i) - p_k) mod 2
```

이 과정을 최하위 비트부터 반복하면 `p`, `q`를 전부 복원할 수 있다.

## 3. Exploit

문제에서 출력된 `n`, `e`, `c`, `mask_p`, `mask_q`를 각각 아래 변수에 넣는다.

```python
# n, e, c, mask_p, mask_q는 문제에서 출력된 값
BITS = 512

p_bits = [0] * BITS
q_bits = [0] * BITS

# 공개된 비트 복원
for i in range(BITS):
    if i & 1:
        p_bits[i] = (mask_p >> i) & 1
    else:
        q_bits[i] = (mask_q >> i) & 1

# p와 q는 홀수 소수
p_bits[0] = 1
q_bits[0] = 1

carry = 0

for k in range(1, BITS):
    middle = sum(
        p_bits[i] * q_bits[k - i]
        for i in range(1, k)
    )

    target = (n >> k) & 1
    partial = carry + middle

    if k & 1:
        # 홀수 위치에서는 p_k가 공개되어 있음
        q_bits[k] = (target - partial - p_bits[k]) & 1
    else:
        # 짝수 위치에서는 q_k가 공개되어 있음
        p_bits[k] = (target - partial - q_bits[k]) & 1

    total = partial + p_bits[k] + q_bits[k]

    assert (total & 1) == target
    carry = total >> 1

p = sum(bit << i for i, bit in enumerate(p_bits))
q = sum(bit << i for i, bit in enumerate(q_bits))

assert p * q == n

phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)

m = pow(c, d, n)
flag = m.to_bytes((m.bit_length() + 7) // 8, "big")

print(flag.decode())
```

## 4. Flag

```text
CTF{Simple_RSA_EZPZ}
```

핵심 취약점은 `p`, `q`의 비트를 서로 엇갈리게 공개했더라도, RSA 곱셈에서 각 단계에 새로 등장하는 두 비트 중 하나를 항상 알고 있기 때문에 다른 하나까지 순차적으로 복구할 수 있다는 점이다.

## 풀고 나서

공개된 비트가 절반뿐이라도, 그 위치가 규칙적이면 나머지 정보와 결합해 복원할 수 있다.

RSA 문제에서는 공개된 숫자의 크기뿐 아니라 **어느 위치의 비트가 알려졌는지**까지 중요한 단서라는 걸 배웠다.

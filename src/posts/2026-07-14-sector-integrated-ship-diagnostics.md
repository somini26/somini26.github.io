## 통합 선박 진단 시스템

### 1. 문제 개요

제공된 압축 파일에는 다음 두 개의 파일이 포함되어 있었다.

* `HexDrift.exe` : 입력값을 암호화하여 화면에 출력하는 Windows 실행 파일
* `enc.mp4` : 프로그램 실행 화면을 녹화한 영상

문제의 목표는 실행 파일과 영상을 분석하여 프로그램 내부에 숨겨진 키 값을 복구하고, 복구된 값이 실제 선박 내부 기기에서 사용하는 키와 관련이 있는지 확인하며, 해당 프로그램이 키 유출을 목적으로 제작되었는지를 검증하는 것이다.

---

### 2. 분석 환경

분석에는 다음과 같은 도구를 사용하였다.

* IDA Free
* Ghidra
* Python 3
* FFmpeg(OpenCV)

---

### 3. 프로그램 분석

실행 파일를 정적 분석한 결과 프로그램은 길이가 **30바이트**인 문자열만 입력받으며 입력 형식은 다음과 같았다.

```text
flag{........................}
```

허용되는 문자는 다음과 같다.

* 숫자(0~9)
* 대문자(A~Z)
* 밑줄(_)

프로그램 내부에는 S-box와 여러 개의 키 배열(K1~K4), 회전량 테이블이 존재하였으며, 입력값은 이를 이용하여 여러 단계의 XOR, 회전(ROL), 치환(S-box), 확산 과정을 거쳐 암호문으로 변환된다.

따라서 단순 문자열 검색만으로는 플래그를 확인할 수 없으며, 암호화 과정을 역순으로 수행하여 원래 입력값을 복원해야 한다.

---

### 4. 영상 분석

실행 결과를 녹화한 `enc.mp4`에서는 다음과 같은 문자열이 반복적으로 출력된다.

```text
#00:1D
#01:1C
...
```

처음에는 이것이 암호문 전체라고 생각하였으나, 프로그램을 분석한 결과 화면에는 암호문의 **하위 5비트만 출력**되고 있었다.

```c
display = ciphertext[i] & 0x1F;
```

나머지 상위 3비트는 문자열의 움직임에 숨겨져 있었다.

분석 결과 다음 요소들이 각각 상위 비트를 의미함을 확인하였다.

* 문자열의 회전 여부
* 회전 방향
* 이동 속도

영상에서 각 문자열의 움직임을 분석하여 상위 3비트를 복원한 뒤, 화면에 표시된 하위 5비트와 결합하여 전체 암호문을 복원하였다.

---

### 5. 복호화

복원한 암호문을 실행 파일의 암호화 과정과 반대 순서로 역연산하였다.

1. 5회의 확산 과정을 역순으로 복원
2. 역 S-box 적용
3. 회전 연산 복원
4. XOR 및 덧셈 연산 복원

복호화 결과 다음 문자열을 얻을 수 있었다.

```text
flag{HUM4N_0CR_BE77ER_7H4N_A1}
```

---

### 6. 선박 내부 기기 키 여부 검증

문제에서는 복구한 값이 실제 선박 내부 장비에서 사용하는 키인지 확인하도록 요구하였다.

프로그램 내부를 분석한 결과,

* 선박 장비와 통신하는 코드가 존재하지 않았고,
* 네트워크(Socket, WinHTTP 등)를 이용하여 데이터를 전송하는 기능도 존재하지 않았으며,
* 실제 선박 장비의 암호키나 식별자를 저장하는 구조 역시 확인되지 않았다.

따라서 복구한 문자열은 실제 선박 장비에서 사용하는 운용 키가 아니라, 문제 해결을 위해 프로그램 내부에 숨겨 놓은 데이터(플래그)로 판단하였다.

---

### 7. 키 유출 목적 여부 검증

프로그램은 암호문 전체를 그대로 출력하지 않고,

* 하위 5비트는 화면에 문자열 형태로 출력하고,
* 상위 3비트는 문자열의 회전과 이동 속도에 숨겨 표현한다.

즉, 실행 화면만 녹화하여 외부로 반출하더라도 암호문 전체를 복원할 수 있는 구조이다.

이러한 방식은 화면을 이용하여 데이터를 은닉하는 **Visual Covert Channel(시각적 은닉 채널)** 기법과 유사하며, 중요 데이터를 화면을 통해 전달하기 위한 구조로 볼 수 있다.

다만 프로그램 내부에는 데이터를 외부 서버로 직접 전송하는 기능이나 실제 선박 장비와 통신하는 기능은 존재하지 않았다.

따라서 본 프로그램은 **실제 악성코드라기보다 화면을 이용한 정보 은닉 및 키 유출 시나리오를 구현한 CTF용 프로그램**으로 판단하였다.

---

### 8. 결론

실행 파일과 실행 영상을 함께 분석하여 암호화 과정을 역으로 복원한 결과 최종 플래그를 획득할 수 있었다.

또한 프로그램 내부에는 실제 선박 장비와 통신하거나 운용 키를 저장하는 기능은 존재하지 않았으며, 화면을 이용한 시각적 정보 은닉(Visual Covert Channel)을 구현한 예제 프로그램임을 확인하였다.

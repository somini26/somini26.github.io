## Flower

### 1. 문제 개요

* 분야: Reversing
* 점수: 500
* 제공 파일: `flower.exe`

문제에서는 프로그램에 입력하는 문자열 자체가 플래그이며, 올바른 값을 입력하면 다음 문자열을 출력한다고 설명되어 있습니다.

```text
Completed!
```

입력 형식은 다음과 같습니다.

```regex
^CTF{[A-Z0-9_]{25}}$
```

따라서 플래그는 `CTF{}` 내부에 대문자, 숫자, 밑줄로 구성된 25글자가 들어가며, 전체 길이는 30글자입니다.

---

### 2. 파일 기본 분석

먼저 `flower.exe`의 파일 형식을 확인했습니다.

```bash
file flower.exe
```

분석 결과, 파일은 64비트 Windows PE 실행 파일이었습니다.

프로그램을 실행하면 사용자로부터 문자열을 입력받고, 입력값이 정답일 경우 `Completed!`를 출력합니다. 따라서 핵심은 입력 문자열을 검사하는 검증 루틴을 찾는 것입니다.

문자열 검색을 통해 다음과 같은 출력 문자열을 확인할 수 있었습니다.

```text
Completed!
```

이 문자열을 참조하는 코드를 역추적하면 성공 여부를 판단하는 분기문과 입력 검증 함수를 찾을 수 있습니다.

---

### 3. 입력 형식 검사

프로그램은 먼저 입력값이 문제에서 제시한 형식과 일치하는지 검사합니다.

조건은 다음과 같습니다.

```text
CTF{
```

로 시작해야 하며, 마지막 문자는 `}`여야 합니다.

중괄호 내부 문자열은 정확히 25글자이고, 사용할 수 있는 문자는 다음과 같습니다.

```text
A-Z
0-9
_
```

따라서 분석 과정에서는 다음과 같은 형태의 입력값을 사용했습니다.

```text
CTF{AAAAAAAAAAAAAAAAAAAAAAAAA}
```

---

### 4. 검증 루틴 분석

검증 함수는 입력 문자열을 한 번에 직접 비교하지 않았습니다.

입력값을 여러 조각으로 나눈 뒤, 각 조각에 대해 별도의 연산을 수행하고 프로그램 내부에 저장된 값과 비교하는 구조였습니다.

또한 검증 코드가 여러 개의 작은 함수로 분리되어 있어 단순히 디컴파일된 코드만 읽어서는 전체 알고리즘을 파악하기 어려웠습니다. 이러한 구조는 분석을 방해하기 위한 일종의 난독화로 볼 수 있습니다.

검증 과정은 대략 다음과 같은 형태였습니다.

```c
input = get_user_input();

if (!check_format(input))
    fail();

for (각 입력 블록) {
    result = transform(input_block);

    if (result != expected_value)
        fail();
}

success();
```

각 블록의 연산 결과가 모두 프로그램 내부의 기준값과 일치해야 성공 분기로 이동합니다.

마지막에는 각 비교 결과를 하나로 합친 뒤, 실패 값이 하나라도 존재하면 실패 메시지를 출력하고, 모든 값이 일치하면 `Completed!`를 출력합니다.

---

### 5. 블록 단위 복원

전체 25글자를 한 번에 전수조사하는 것은 경우의 수가 너무 많습니다.

허용 문자는 대문자 26개, 숫자 10개, 밑줄 1개로 총 37개이므로 전체 경우의 수는 다음과 같습니다.

```text
37^25
```

따라서 검증 알고리즘이 입력을 나누어 처리한다는 점을 이용해 블록 단위로 값을 복원했습니다.

먼저 후보 문자열을 검증 함수에 입력하고, 각 블록의 중간 연산 결과를 프로그램 내부의 정답 값과 비교했습니다.

첫 번째 부분을 분석한 결과 다음 문자열이 정답과 일치했습니다.

```text
FLOWER
```

이후 동일한 방법으로 다음 블록들을 순서대로 복원했습니다.

```text
FLOWERS
FLOWERS_ALWAYS
FLOWERS_ALWAYS_SMILE
```

마지막 부분은 일반적인 단어가 아니라 숫자와 문자가 섞인 형태였습니다.

허용 문자 범위 내에서 마지막 블록을 검사한 결과 다음 값이 정답과 일치했습니다.

```text
0XFF
```

이를 모두 결합하면 중괄호 내부의 25글자는 다음과 같습니다.

```text
FLOWERS_ALWAYS_SMILE_0XFF
```

글자 수를 확인하면 정확히 25글자입니다.

```text
FLOWERS       → 7글자
_             → 1글자
ALWAYS        → 6글자
_             → 1글자
SMILE         → 5글자
_             → 1글자
0XFF          → 4글자

총 25글자
```

### 6. 최종 검증

복원한 문자열을 프로그램에 입력했습니다.

```text
CTF{FLOWERS_ALWAYS_SMILE_0XFF}
```

입력 결과 프로그램이 성공 메시지를 출력했습니다.

```text
Completed!
```

따라서 최종 플래그를 확인할 수 있었습니다.

### 8. 정리

이 문제는 입력값 전체를 직접 비교하는 방식이 아니라, 입력을 여러 블록으로 나누어 변환한 후 내부의 기준값과 비교하는 리버싱 문제였습니다.

검증 루틴이 많은 작은 함수로 분리되어 있어 정적 분석만으로는 흐름을 파악하기 어려웠지만, 성공 문자열인 `Completed!`의 참조 지점에서 역추적하여 최종 비교 루틴을 찾을 수 있었습니다.

이후 검증 함수의 중간 결과를 관찰하고 입력을 블록 단위로 대입함으로써 전체 문자열을 복원했습니다.

핵심 풀이 과정은 다음과 같습니다.

```text
입력 형식 확인
→ Completed! 참조 지점 탐색
→ 입력 검증 함수 확인
→ 블록 단위 변환 구조 파악
→ 각 블록의 정답값 복원
→ 프로그램에 최종 입력하여 검증
```

읽어주셔서 감사합니다. (꾸벅)

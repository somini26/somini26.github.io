이번에는 2026년에 진행한 기술 활동을 돌아보고, 그 과정에서 느꼈던 재미와 고민, 앞으로 보완하고 싶은 부분을 정리해 보려고 합니다. 관심이 생긴 주제를 직접 해보는 일이 많았고, 어떤 것은 하나씩 끝까지 분석했으며 처음 접한 기술은 기본 개념부터 다시 공부해야 했습니다.

연말이 가까워지면서 활동 기록을 모아 보니 해본 일은 꽤 많았는데요. 단순히 활동 목록만 늘어난 것은 아니었습니다. 처음에는 낯설기만 했던 도구가 조금씩 재미있어지기도 했고, 문제를 풀고 나서도 제가 정말 원리를 이해한 것인지 고민하게 된 순간도 있었습니다. 올해 무엇을 경험했고, 그 경험이 앞으로의 공부 방향에 어떤 영향을 주었는지 차근차근 돌아보겠습니다.

## 1. 처음 제대로 참가해 본 CTF

올해 가장 기억에 남는 활동은 CTF 대회에 본격적으로 참가해 본 경험입니다. 처음 참가하는 대회들이라 대회의 진행 방식과 문제 구성이 모두 신기하게 느껴졌습니다. 공부하면서 접했던 문제와 비슷한 유형이 실제 대회에 나오기도 했고, 반대로 전혀 예상하지 못한 부분이 문제의 핵심이 되기도 했습니다.

문제를 처음 열었을 때는 무엇부터 확인해야 할지 막막한 경우가 많았습니다. 그래도 제공된 파일과 실행 결과를 하나씩 살펴보고, 눈에 띄는 단서를 따라가면서 가능한 접근 방법을 찾아보았습니다. 처음에는 보이지 않던 흐름이 분석을 이어갈수록 조금씩 연결되고, 결국 해결 방법을 찾아 플래그를 확인했을 때의 기분이 정말 좋았습니다. 모든 문제를 혼자 해결하거나 대회마다 좋은 결과를 얻은 것은 아니지만, 막막했던 문제를 조금씩 이해해 가는 과정 자체가 CTF의 큰 재미라는 생각이 들었습니다.

7월 SECTOR에서는 선박 사진 업로드, HexDrift 영상 분석, 위성 인증 에이전트, 로봇 동작 궤적처럼 서로 다른 유형의 문제를 풀어보았습니다. 같은 대회 안에서도 웹 요청을 확인해야 하는 문제와 프로그램의 검증 로직을 따라가야 하는 문제, 영상이나 궤적에서 정보를 찾아야 하는 문제의 접근 방식이 모두 달랐습니다.

7월 연합 CTF에서는 Hollow Notes와 Flower의 리버싱, Notekeeper의 메모리 취약점, Déjà Vu와 지그재그의 암호학, Stellar Salvage와 답지유출의 웹 취약점, AI 관련 두 문제를 경험했습니다. 공부했던 개념이 실제 문제에서는 어떤 모습으로 변형되어 나오는지 살펴볼 수 있었고, 한 가지 방식만 고집하기보다 문제에 맞춰 생각을 바꾸는 연습도 필요하다는 점을 느꼈습니다.

9월 HACKSIUM에서는 Wazuh 로그, HQ-DC01 관련 분석, 원격 실습 환경과 Bastion 관련 문제를 접했습니다. 개별 파일만 보는 것이 아니라 여러 시스템의 상태와 로그를 연결해서 전체 상황을 읽는 연습이 필요하다는 점을 알게 되었습니다.

이런 경험을 하면서 CTF는 단순히 보안 지식을 확인하는 문제가 아니라, 주어진 단서를 바탕으로 여러 가능성을 생각하고 직접 해결 방법을 찾아가는 활동이라고 느꼈습니다. 공부한 내용이 문제 해결로 이어질 때도 재미있었지만, 예상하지 못했던 분야를 만나 새롭게 공부할 이유가 생기는 점도 좋았습니다.

## 2. GDB와 BombLab, 그리고 관심 분야의 변화

BombLab을 시작하기 전, 개인으로 처음 참가했던 CTF에서 GDB를 사용한 적이 있습니다. 당시에는 GDB 사용법을 제대로 알지 못해서 프로그램을 종료하거나 GDB에서 빠져나오는 방법조차 몰랐습니다. 지금 생각하면 간단한 명령어 하나의 문제였지만, 그때는 디버깅 도구 자체가 너무 낯설어서 한참을 헤맸던 기억이 남아 있습니다.

이후 개인 프로젝트로 BombLab을 진행하면서 GDB를 본격적으로 공부하게 되었습니다. 순정 GDB로 어셈블리 코드를 읽고 레지스터와 메모리의 값을 확인하면서, 프로그램이 어떤 조건에서 다음 단계로 넘어가는지 하나씩 추적했습니다. 문자열 비교부터 수열, 분기문, 재귀 함수, 비트 연산과 연결 리스트까지 각 Phase의 검증 방식이 달랐기 때문에 정답만 추측해서는 해결하기 어려웠습니다.

물론 처음부터 순조롭게 풀리지는 않았습니다. 잘못된 입력을 넣어 폭탄을 터뜨리기도 했고, 예상했던 분기와 실제 실행 흐름이 달라 다시 어셈블리 코드를 살펴본 적도 있었습니다. 하지만 왜 폭탄이 터졌는지 확인하고 다음 입력을 다시 생각하는 과정이 재미있었습니다. 공부하고 있다는 느낌과 게임을 하고 있다는 느낌이 동시에 들었던 점이 특히 인상 깊었습니다.

각 Phase를 해결한 뒤에는 `explode_bomb` 함수의 기계어를 직접 패치해 프로그램의 동작이 어떻게 달라지는지도 확인해 보았습니다. 정답을 찾는 것과 프로그램이 그 정답을 판단하는 과정을 이해하는 것은 확실히 달랐습니다. 예전에는 종료 방법조차 몰라 당황했던 GDB로 실행 흐름을 따라가고 바이너리까지 수정해 보니, 조금씩 도구를 이해하고 있다는 느낌이 들었습니다.

이 경험을 통해 프로그램의 내부 동작을 직접 분석하는 일에도 흥미가 생겼습니다. 처음 CTF에서 GDB를 제대로 사용하지 못했던 경험이 BombLab을 통해 도구를 공부하는 과정으로 이어졌고, 직접 문제를 해결하는 재미를 느끼면서 시스템 해킹과 리버싱을 더 공부해 보고 싶다고 생각하게 되었습니다.

## 3. 다른 보안 분야와 기록 활동

CodeQL 실습에서는 사용자 입력이 `os.system()` 같은 위험 함수로 전달되는 데이터 흐름을 탐색해 보았습니다. ARM PAC 같은 방어 기술도 조사하고, 세미나 자료를 정리하면서 공격뿐 아니라 방어의 관점도 함께 배우려고 했습니다.

그리고 티스토리에서 정리하던 내용을 GitHub Pages 블로그로 옮겨 더 오래 쌓아갈 기반을 만들었습니다. 기록 자체도 하나의 프로젝트라는 생각이 들었습니다.

여러 활동을 한곳에 정리하면서 같은 문제를 풀었더라도 어떤 근거와 과정을 남겼는지에 따라 나중에 다시 이해하기 쉬운 정도가 크게 달라진다는 점도 알게 되었습니다. 블로그를 만드는 일뿐 아니라, 제가 확인한 사실과 생각의 흐름을 다른 시점의 저도 이해할 수 있게 적는 일까지 기록 활동의 일부라고 느꼈습니다.

## 4. 공부하면서 느낀 부족함

처음 CTF 문제를 접했을 때는 기본기가 많이 부족하다고 느꼈습니다. 쉬운 문제라고 소개된 문제도 어디서부터 접근해야 할지 몰랐고, 문제를 읽어도 무엇을 분석해야 하는지 감이 잡히지 않을 때가 있었습니다. 단순히 사용할 도구를 모르는 것뿐 아니라, 문제에서 요구하는 개념 자체를 충분히 이해하지 못한 경우도 있었습니다.

어셈블리, 운영체제, 네트워크, 암호학처럼 개별 개념을 따로 공부해도 실제 문제에서는 여러 내용을 동시에 연결해야 했습니다. 낯선 문제에서 핵심을 찾기까지 시간이 오래 걸리는 이유도 이 연결이 아직 익숙하지 않기 때문이라고 생각했습니다. 새로운 분야를 접하는 재미는 계속 가져가고 싶지만, 넓게 살펴보는 것만으로는 해결되지 않는 부분이 있다는 사실도 느꼈습니다.

풀이를 재현할 수 있는 형태로 정리하는 습관도 부족했습니다. 당시에는 플래그를 찾는 데 집중하다 보니 실패한 시도, 사용한 명령어, 검증 과정을 충분히 남기지 못할 때가 있었습니다. 시간이 지난 뒤 다시 보면 왜 이런 결론을 내렸는지 바로 이해하기 어려웠습니다. 한 번 사용한 전략을 다른 문제에도 적용하려면 결과뿐 아니라 그 방법이 통했던 조건과 한계까지 정리해야 한다는 점을 알게 되었습니다.

### AI를 활용하면서 생긴 고민

보안 분야를 공부하면서 AI와 GPT를 활용하는 일이 많아졌는데요. 이해하지 못한 개념을 질문하거나, 문제를 분석하다 막힌 부분과 제가 생각한 접근을 이야기하면서 도움을 받은 적이 있습니다. 어려운 설명을 다시 풀어보거나 제가 미처 생각하지 못한 접근 방법을 찾는 데 분명히 도움이 되었습니다.

그러면서 한편으로는 **“과연 AI가 없으면 나는 이런 문제를 혼자 풀 수 있을까?”**라는 고민도 생겼습니다. AI의 설명을 읽을 때는 이해한 것 같았지만, 막상 아무런 도움 없이 처음부터 같은 문제를 분석하라고 하면 같은 방식으로 해결할 수 있을지 확신이 서지 않을 때가 있었습니다.

AI를 사용하는 것이 잘못됐다고 생각하지는 않습니다. 모르는 내용을 이해하고 새로운 관점을 찾는 데 유용한 도구라고 생각합니다. 다만 AI가 알려준 해결 방법을 그대로 따라가는 것과, 그 방법이 왜 동작하는지 제가 이해하고 설명할 수 있는 것은 다릅니다. 도움을 받은 뒤에는 같은 과정을 직접 다시 확인하고, 각 단계의 근거를 제 말로 설명해 보는 시간이 필요하다고 느꼈습니다.

앞으로는 플래그를 찾거나 정답을 확인하는 데서 끝내지 않고, 왜 그런 방법으로 해결되는지 스스로 설명할 수 있을 만큼 공부하고 싶습니다. 부족함을 느낀 경험을 단순한 자신감의 문제로 남기기보다, 어떤 기본기를 더 공부해야 하는지 알려주는 기준으로 삼으려고 합니다.

## 5. 앞으로 실천하고 싶은 계획

### 보안 동아리 스터디에 꾸준히 참여하기

동아리에서 진행하는 시스템 및 보안 관련 스터디에 꾸준히 참여하고 싶습니다. 단순히 자리에 참석하는 것으로 끝내지 않고, 해당 주차에 배울 내용을 미리 공부하고 직접 실습해 보면서 제대로 이해하려고 합니다. 스터디에서 알게 된 개념도 이후 문제 분석이나 작은 실습에 다시 적용해 보고 싶습니다.

### 나이츠 프론티어 미션에 계속 도전하기

필수 미션만 완료하는 데 그치지 않고, 다양한 미션에도 꾸준히 도전해 보고 싶습니다. 아직 익숙하지 않은 기술이나 활동을 접할 수 있는 기회라고 생각하기 때문에, 처음부터 잘할 수 있는 분야만 고르기보다 새로운 분야에도 직접 부딪혀 보려고 합니다.

### CTF 문제를 풀고 끝내지 않기

지금까지는 문제를 풀고 플래그를 얻은 뒤 라이트업을 작성하면 하나의 활동을 마쳤다고 생각하는 경우가 많았습니다. 앞으로는 라이트업을 작성한 이후에도 사용했던 기법을 다시 공부하고, 취약점이 왜 발생했으며 어떤 원리로 해결할 수 있었는지 더 깊이 이해하고 싶습니다.

시간이 지난 뒤 같은 문제를 다시 분석하면서, 이전에 공부했던 내용을 도움 없이도 설명하고 적용할 수 있는지 확인해 보는 것도 좋은 방법일 것 같습니다. 풀이를 기록할 때는 다음 내용을 빠뜨리지 않으려고 합니다.

1. 문제의 목표와 제공 파일
2. 주요 단서와 시도한 접근
3. 성공 여부와 그 근거를 확인한 방법
4. 다시 활용할 수 있는 전략과 실패 이유

이렇게 정리하면 플래그를 얻은 순간뿐 아니라 문제를 이해해 가는 과정까지 남길 수 있을 것 같습니다.

### 시스템 해킹의 기본기 쌓기

시스템 해킹을 공부하려면 어셈블리어뿐 아니라 컴퓨터가 프로그램을 실행하는 기본 원리도 중요하다고 느꼈습니다. 아직 기초 지식이 충분하지 않기 때문에 C와 x86-64 어셈블리, 컴퓨터구조, 운영체제, 메모리와 프로세스 개념을 차근차근 연결해서 공부하려고 합니다.

특히 GDB를 몇 가지 명령어만 외워 사용하는 도구로 남겨두고 싶지는 않습니다. 레지스터와 메모리 상태를 직접 확인하고, 명령어가 실행될 때 프로그램의 흐름이 어떻게 바뀌는지 이해하는 데 활용할 수 있도록 연습하고 싶습니다. 동시에 웹·암호학·AI 등 다른 분야도 계속 탐색하면서 관심 분야를 너무 일찍 좁혀 두지는 않으려고 합니다.

### 작은 실습을 직접 만들기

공부한 취약점을 작은 로컬 예제로 재현하고, 방어 방법을 적용했을 때 실제로 차단되는지도 확인해 보고 싶습니다. 이렇게 하면 라이트업이나 AI의 설명을 읽는 데서 멈추지 않고, 개념이 실제 코드와 실행 결과에서 어떻게 나타나는지 직접 확인할 수 있을 것 같습니다.

### 공부한 내용 꾸준히 기록하기

새롭게 배운 기술이나 해결한 문제는 블로그에 꾸준히 기록하고 싶습니다. 단순히 문제 풀이 결과만 남기기보다 나중에 다시 읽었을 때 왜 그렇게 분석했는지 이해할 수 있는 글을 작성하려고 합니다. 대회가 끝난 뒤에만 몰아서 작성하기보다는, 완벽한 글을 쓰느라 미루지 않고 **실제로 확인한 사실과 생각의 흐름을 정확하게 남기는 것**부터 시작하고 싶습니다.

## 6. 2026년을 돌아보며

돌아보니 올해는 새로운 대회와 도구를 접하면서 제가 어떤 과정에서 재미를 느끼는지 알게 된 해였습니다. 막막했던 문제를 하나씩 분석해 해결 방법을 찾는 과정, GDB로 프로그램 내부를 따라가며 이전에는 보이지 않던 흐름을 이해하는 과정이 특히 기억에 남습니다.

동시에 다양한 경험을 쌓는 것만큼 **그 경험을 제 실력으로 연결하는 방법**이 중요하다는 점도 느꼈습니다. AI의 도움을 받았더라도 해결 과정을 다시 검증하고, 한 번 접한 개념은 제 말로 설명할 수 있을 때까지 공부해 보려고 합니다. 지금 세운 계획들이 이미 달성한 결과는 아니지만, 앞으로 무엇을 공부하고 어떤 방식으로 기록할지 정하는 기준이 될 것 같습니다.

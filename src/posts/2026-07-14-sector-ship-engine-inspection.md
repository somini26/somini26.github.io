7월 14일 SECTOR에서 풀었던 **선박 기관 점검 시스템**은 사진 업로드 기능을 살펴보는 웹 문제였다.

처음에는 `getimagesize()`로 이미지 파일을 확인하니 업로드가 제한될 것처럼 보였다. 그런데 코드를 조금 더 보니 파일 이름과 확장자는 그대로 유지했고, 업로드 경로에서도 PHP가 실행될 수 있었다. 이 두 조건을 연결하는 게 풀이의 출발점이었다.

아래에는 어떤 부분을 확인했고 어떻게 `/flag`에 도달했는지 당시 기록을 기준으로 정리했다.

---

## 1. 문제 개요

해금강-IX 스마트 선박에서 운영되는 기관 점검 시스템의 사진 업로드 기능을 분석하여 취약점을 찾고, 이를 이용해 서버 내부 `/flag` 파일의 내용을 획득하는 문제이다.

문제 설명에 따르면 공격자는 점검 사진 등록 기능을 악용하여 웹 서버에 임의의 파일을 업로드한 뒤, 이를 실행하여 시스템 내부 파일에 접근한 것으로 확인되었다. 따라서 사진 업로드 기능을 중심으로 취약점을 분석하였다.

---

## 2. 취약점 분석

사진 등록 기능을 확인한 결과, 업로드된 파일에 대해 `getimagesize()` 함수를 이용하여 이미지 여부만 검사하고 있었다.

```php
$image_info = getimagesize($_FILES["photo"]["tmp_name"]);

if ($image_info === false) {
    exit();
}

$target_file = $target_dir . basename($_FILES["photo"]["name"]);

move_uploaded_file($_FILES["photo"]["tmp_name"], $target_file);
```

해당 코드에는 다음과 같은 보안상의 문제가 존재하였다.

* `getimagesize()`를 이용한 이미지 여부만 검사하고 파일 확장자는 검증하지 않는다.
* 업로드한 파일명을 그대로 사용한다.
* 업로드된 파일이 웹 서버에서 접근 가능한 디렉터리에 저장된다.
* 업로드 디렉터리에서 PHP 파일 실행이 가능하다.

즉, 이미지처럼 보이는 PHP 파일을 업로드할 수 있다면 서버에서 임의의 PHP 코드가 실행될 수 있는 환경이었다.

---

## 3. 공격 과정

취약점을 이용하기 위해 정상적인 GIF 헤더와 PHP 코드를 함께 포함한 **GIF/PHP Polyglot** 파일을 제작하였다.

실행에 사용한 PHP 코드는 다음과 같다.

```php
<?php
echo file_get_contents('/flag');
?>
```

파일 앞부분에는 GIF 헤더를 삽입하여 `getimagesize()` 검사를 통과하도록 만들었으며, 파일명은 `shell.php`로 지정하여 업로드하였다.

공격 과정은 다음과 같다.

1. 회원가입 후 로그인한다.
2. GIF/PHP Polyglot 파일을 `shell.php`라는 이름으로 업로드한다.
3. 메인 페이지에서 업로드된 파일의 경로를 확인한다.
4. `/uploads/{uuid}/shell.php`에 접속한다.
5. 업로드된 PHP 파일이 실행되면서 `/flag` 파일의 내용을 출력한다.

업로드 디렉터리에서 PHP 실행이 허용되어 있었기 때문에 업로드한 파일이 그대로 실행되었고, 서버 내부 파일을 읽을 수 있었다.

---

## 4. 취약점 원인

취약점이 발생한 원인은 다음과 같다.

* 이미지 여부만 검사하고 확장자를 제한하지 않음
* 업로드한 파일명을 그대로 저장함
* 업로드 디렉터리가 웹에서 접근 가능함
* 업로드 디렉터리에서 PHP 실행이 가능함

이러한 설정으로 인해 공격자는 악성 PHP 파일을 업로드하여 원격 코드 실행(Remote Code Execution, RCE)을 수행할 수 있었다.

---

## 5. 대응 방안

해당 취약점을 방지하기 위해서는 다음과 같은 보안 대책이 필요하다.

* 허용된 이미지 확장자(`jpg`, `jpeg`, `png`, `gif`)만 업로드하도록 제한한다.
* 업로드 시 서버에서 랜덤한 파일명을 생성한다.
* MIME Type과 파일 확장자를 함께 검증한다.
* 업로드 파일을 웹 루트(Document Root) 외부에 저장한다.
* 업로드 디렉터리에서 PHP 실행을 차단한다.

위와 같은 보안 조치를 적용하면 악성 파일 업로드와 원격 코드 실행을 효과적으로 방지할 수 있다.

---

## 6. 결론

사진 업로드 기능의 검증 로직을 분석한 결과, 이미지 여부만 검사하고 파일 확장자 및 실행 가능 여부를 검증하지 않는 취약점이 존재하였다.

이를 이용해 GIF/PHP Polyglot 파일을 업로드하고 웹 서버에서 실행함으로써 서버 내부의 `/flag` 파일을 읽을 수 있었으며, 최종적으로 플래그를 획득하였다.

## 풀고 나서

`getimagesize()`를 통과했다는 사실과 **안전한 파일**이라는 결론은 다르다. 업로드 경로, 확장자, 실행 권한을 따로 확인해야 한다는 걸 이 문제에서 확실히 봤다.

웹 문제를 풀 때는 기능이 정상적으로 동작하는지만 보지 말고, 파일이 저장된 뒤 서버에서 **어떻게 취급되는지**까지 살펴봐야겠다.

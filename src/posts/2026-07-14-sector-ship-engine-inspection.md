## 선박 기관 점검 시스템

### 1. 문제 개요

해금강-IX 스마트 선박에서 운영되는 기관 점검 시스템의 사진 업로드 기능을 분석하여 취약점을 찾고, 이를 이용해 서버 내부 `/flag` 파일의 내용을 획득하는 문제입니다.

문제 설명에 따르면 공격자는 점검 사진 등록 기능을 악용하여 웹 서버에 임의의 파일을 업로드한 뒤, 이를 실행하여 시스템 내부 파일에 접근한 것으로 확인됐습니다. 따라서 사진 업로드 기능을 중심으로 취약점을 분석했습니다.

---

### 2. 취약점 분석

사진 등록 기능을 확인한 결과, 업로드된 파일에 대해 `getimagesize()` 함수를 이용하여 이미지 여부만 검사하고 있었습니다.

```php
$image_info = getimagesize($_FILES["photo"]["tmp_name"]);

if ($image_info === false) {
    exit();
}

$target_file = $target_dir . basename($_FILES["photo"]["name"]);

move_uploaded_file($_FILES["photo"]["tmp_name"], $target_file);
```

해당 코드에는 다음과 같은 보안상의 문제가 존재했습니다.

* `getimagesize()`를 이용한 이미지 여부만 검사하고 파일 확장자는 검증하지 않습니다.
* 업로드한 파일명을 그대로 사용합니다.
* 업로드된 파일이 웹 서버에서 접근 가능한 디렉터리에 저장됩니다.
* 업로드 디렉터리에서 PHP 파일 실행이 가능합니다.

즉, 이미지처럼 보이는 PHP 파일을 업로드할 수 있다면 서버에서 임의의 PHP 코드가 실행될 수 있는 환경이었습니다.

---

### 3. 공격 과정

취약점을 이용하기 위해 정상적인 GIF 헤더와 PHP 코드를 함께 포함한 **GIF/PHP Polyglot** 파일을 제작했습니다.

실행에 사용한 PHP 코드는 다음과 같습니다.

```php
<?php
echo file_get_contents('/flag');
?>
```

파일 앞부분에는 GIF 헤더를 삽입하여 `getimagesize()` 검사를 통과하도록 만들었으며, 파일명은 `shell.php`로 지정하여 업로드했습니다.

공격 과정은 다음과 같습니다.

1. 회원가입 후 로그인합니다.
2. GIF/PHP Polyglot 파일을 `shell.php`라는 이름으로 업로드합니다.
3. 메인 페이지에서 업로드된 파일의 경로를 확인합니다.
4. `/uploads/{uuid}/shell.php`에 접속합니다.
5. 업로드된 PHP 파일이 실행되면서 `/flag` 파일의 내용을 출력합니다.

업로드 디렉터리에서 PHP 실행이 허용되어 있었기 때문에 업로드한 파일이 그대로 실행되었고, 서버 내부 파일을 읽을 수 있었습니다.

---

### 4. 취약점 원인

취약점이 발생한 원인은 다음과 같습니다.

* 이미지 여부만 검사하고 확장자를 제한하지 않음
* 업로드한 파일명을 그대로 저장함
* 업로드 디렉터리가 웹에서 접근 가능함
* 업로드 디렉터리에서 PHP 실행이 가능함

이러한 설정으로 인해 공격자는 악성 PHP 파일을 업로드하여 원격 코드 실행(Remote Code Execution, RCE)을 수행할 수 있었습니다.

---

### 5. 대응 방안

해당 취약점을 방지하기 위해서는 다음과 같은 보안 대책이 필요합니다.

* 허용된 이미지 확장자(`jpg`, `jpeg`, `png`, `gif`)만 업로드하도록 제한합니다.
* 업로드 시 서버에서 랜덤한 파일명을 생성합니다.
* MIME Type과 파일 확장자를 함께 검증합니다.
* 업로드 파일을 웹 루트(Document Root) 외부에 저장합니다.
* 업로드 디렉터리에서 PHP 실행을 차단합니다.

위와 같은 보안 조치를 적용하면 악성 파일 업로드와 원격 코드 실행을 효과적으로 방지할 수 있습니다.

---

### 6. 결론

사진 업로드 기능의 검증 로직을 분석한 결과, 이미지 여부만 검사하고 파일 확장자 및 실행 가능 여부를 검증하지 않는 취약점이 존재했습니다.

이를 이용해 GIF/PHP Polyglot 파일을 업로드하고 웹 서버에서 실행함으로써 서버 내부의 `/flag` 파일을 읽을 수 있었으며, 최종적으로 플래그를 획득했습니다.

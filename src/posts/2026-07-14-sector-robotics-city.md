## 로봇 혁신 도시

### 1. 문제 개요

경남 창원의 스마트제조 실증단지에 위치한 가상의 기업 한려로보틱스는 산업용 휴머노이드 로봇 `GARO-7`의 시연을 준비하고 있었다.

그러나 박람회 전날 밤, `GARO-7`은 예정에 없던 동작을 수행하였다. 로봇은 오른팔을 들어 올린 뒤 검지 끝으로 허공에 특정한 궤적을 그렸지만, 화면에는 글자나 이동 흔적이 직접 표시되지 않았다.

제공된 파일은 다음과 같다.

```text
robotics_city.run
```

이 문제의 목적은 실행 기록에 저장된 로봇의 움직임을 분석하고, 검지 끝이 그린 문자열을 복원하는 것이다.

플래그 형식은 다음과 같다.

```text
flag{lowercase}
```

---

### 2. 파일 분석

먼저 `robotics_city.run` 파일의 형식을 확인하였다.

해당 파일은 일반적인 실행 파일이나 영상 파일이 아니라, Windows 프로그램의 실행 상태가 저장된 디버깅 기록 형태였다. 기록을 분석한 결과, 로봇 시뮬레이션 프로그램과 별도의 움직임 데이터가 사용된 것을 확인할 수 있었다.

움직임 데이터에는 시간에 따른 로봇의 관절값과 위치 정보가 연속적으로 저장되어 있었다.

문제 설명에서 특히 중요한 부분은 다음 문장이다.

```text
로봇은 오른팔을 들어 올린 뒤, 검지 끝으로 허공에 무언가를 천천히 그려 나갔다.
```

따라서 단순히 로봇의 관절값을 확인하는 것이 아니라, 각 프레임에서 검지 끝의 위치를 추적하여 이동 경로를 복원해야 한다고 판단하였다.

---

### 3. 검지 끝 궤적 복원

움직임 기록에서 검지 끝의 좌표를 시간순으로 추출한 뒤, 각 좌표를 2차원 평면 위에 점과 선으로 연결하였다.

개념적인 처리 과정은 다음과 같다.

```python
points = []

for frame in motion_data:
    x = frame.finger_x
    y = frame.finger_y
    points.append((x, y))

for i in range(len(points) - 1):
    draw_line(points[i], points[i + 1])
```

전체 좌표를 단순히 하나의 선으로 연결하면, 글자 사이를 이동하는 과정에서 발생한 불필요한 선까지 함께 표시되어 문자열을 판독하기 어려워진다.

이를 해결하기 위해 연속된 두 좌표 사이의 변화량을 계산하였다.

```python
dx = x2 - x1
dy = y2 - y1
distance = (dx * dx + dy * dy) ** 0.5
```

좌표 간 거리가 일정 기준보다 큰 경우에는 서로 다른 글자 또는 획 사이를 이동한 것으로 판단하고 선을 연결하지 않았다. 이를 통해 실제로 문자를 그리는 구간과 단순 이동 구간을 분리할 수 있었다.

또한 좌표계의 방향에 따라 문자열이 상하 또는 좌우로 반전되어 나타날 수 있으므로, 축 반전과 회전을 적용하여 사람이 읽을 수 있는 방향으로 보정하였다.

```python
plt.plot(xs, [-y for y in ys])
plt.axis("equal")
```

필터링된 궤적을 시각화한 결과, 여러 개의 영문자와 숫자로 구성된 문자열을 확인할 수 있었다.

---

### 4. 궤적 문자열 판독

복원된 궤적은 다음과 같이 읽혔다.

```text
FLAG{4U7ON0MOUS_6OT_SK3TCH3S_NE0N_C1TY}
```

해당 문자열은 일반적인 영단어와 비슷하게 보이지만, 일부 문자가 리트스피크 형태로 표현되어 있다.

대표적인 대응 관계는 다음과 같다.

```text
4 → A
7 → T
0 → O
3 → E
1 → I
```

하지만 문제에서는 문자열의 의미에 맞게 문자를 변환하는 것이 아니라, 로봇이 실제로 그린 문자와 숫자를 그대로 제출해야 한다.

특히 첫 번째 단어는 다음과 같이 판독된다.

```text
4U7ON0MOUS
```

이를 의미에 맞게 임의로 수정하거나, 모양이 유사한 숫자와 알파벳을 잘못 구분하면 올바른 플래그가 되지 않는다.

두 번째 단어 역시 일반적인 `BOT`이 아니라, 궤적에 나타난 숫자 `6`을 유지한 다음 문자열로 판독해야 한다.

```text
6OT
```

따라서 궤적에 나타난 숫자, 알파벳, 언더바를 모두 원문 그대로 유지해야 한다.

---

### 5. 대소문자 변환

복원된 문자열은 대문자로 표시되어 있었지만, 문제에서 제시한 플래그 형식은 `lowercase`였다.

따라서 알파벳만 소문자로 변환하고 숫자와 언더바는 그대로 유지하였다.

```text
FLAG{4U7ON0MOUS_6OT_SK3TCH3S_NE0N_C1TY}
```

변환 결과는 다음과 같다.

```text
flag{4u7on0mous_6ot_sk3tch3s_ne0n_c1ty}
```

### 7. 결론

이 문제는 Windows 실행 기록에 포함된 로봇의 움직임 데이터를 분석하여, 검지 끝이 이동한 경로를 시각적으로 복원하는 문제였다.

전체 풀이 과정은 다음과 같다.

1. `robotics_city.run` 실행 기록의 형식 확인
2. 로봇의 움직임 데이터 및 좌표 정보 분석
3. 시간에 따른 검지 끝 좌표 추출
4. 좌표를 2차원 평면에 시각화
5. 글자 사이의 이동 구간을 제거하여 궤적 정리
6. 숫자와 알파벳이 혼합된 문자열 판독
7. 문제 조건에 맞게 알파벳을 소문자로 변환

이 문제에서 가장 중요한 점은 궤적의 의미를 추측하여 일반적인 영어 문장으로 교정하는 것이 아니라, 실제 궤적에 나타난 숫자와 알파벳을 정확히 구별하여 그대로 제출하는 것이다.
